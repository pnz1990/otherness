> Status: Complete | Created: 2026-04-20

## What this does

Makes `/otherness.onboard` reliably produce a complete `docs/aide/` set for any
standard project without requiring manual editing. The acceptance criterion is:
after running `/otherness.onboard`, `/otherness.run` starts autonomously without
any human corrections to the generated files.

- 🔲 `AGENTS.md` staleness detection for running projects — onboarded months ago but project has evolved: a project that was onboarded successfully runs otherness for months. During that time: the CLI binary changes name, the build command changes, the repo description updates, new team members join and the architecture evolves significantly. `AGENTS.md` still reflects the state of the project on onboarding day. `/otherness.run` reads this stale context and makes decisions based on it — generating queue items that reference outdated architecture, claiming work against a CLI that no longer exists, writing specs that assume the old build system. There is no mechanism that detects when `AGENTS.md` has drifted from the current project reality. Without this check, otherness can run for 200 batches on a project that has fundamentally changed its architecture, making decisions based on a description that no longer matches reality — the most insidious form of stale context because it looks correct. ⚠️ Inferred from onboarding lens: a new project added today would still require significant human intervention to get running — but the deeper problem is that a project added 6 months ago may be running successfully in terms of batch count while making systematically wrong decisions because `AGENTS.md` describes a project that no longer exists; there is no periodic check that detects this drift.
